# PRD：多宫格拼图工具 v1.4 工作台改版

状态：第一阶段已实现

日期：2026-10-09

负责人：待定

目标发布：2026-10-09 第一阶段部署

## 1. 背景

当前版本已经具备自动网格、图片检测、网格画布、图片涂抹和人像抠图五项可用能力，并且所有处理均在浏览器本地完成。但现有页面从视觉展示出发，背景视频、流动背景、小黑龙动画、双重导航和大量并排控件共同竞争注意力；同时约 19.8MB 的人像运行资源在首页直接加载，与用户当前任务无关。

本次改版不重写核心算法。目标是在保持五项能力和本地处理承诺的前提下，把产品整理成更快、更可信、更易理解的日常图片工作台。

## 2. 用户问题

目标用户想尽快把一批图片处理成可交付文件，但当前版本存在四个核心阻力：

1. 打开后不知道应先看左侧导航、顶部标签还是中间控件。
2. 普通拼图也要加载人像模型，首次体验偏重。
3. 设置与主操作混在一行，无法形成清楚的下一步。
4. 提示、错误和确认大量脱离页面，批量处理被反复打断。

## 3. 目标与非目标

### 目标

- 用户在 10 秒内理解产品能做什么，并开始上传图片。
- 自动网格的主路径收敛为“上传 → 调整 → 生成/下载”。
- 未进入人像抠图前不加载人像推理库和模型数据。
- 五项现有工具保持功能可用，导出结果不发生非预期变化。
- 页面在 320、375、414、768px 宽度下无横向溢出，主要控件可触控。
- 所有主操作可用键盘到达，并有可见焦点状态。

### 非目标

- 不新增用户账号、后端、云存储或多人协作。
- 不引入在线素材库和模板市场。
- 不在本期开发完整文字、贴纸、滤镜和图层系统。
- 不将图片发送给第三方模型或服务器。

## 4. 用户画像与场景

### 主要用户

- 内容/短剧运营：批量检查素材大小与像素，快速生成多图封面。
- 电商与社媒运营：按常用比例整理商品图、对比图和平台图片。
- 日常办公用户：不学习专业软件，快速拼图、改尺寸、遮挡信息或抠图。

### 核心场景

- “我有 6 张图片，要在一分钟内做成一张整齐的 1:1 拼图。”
- “我要确认一批图片是否超过 20MB 或不符合像素要求，并处理异常项。”
- “我要自己排一个 3×3 画布，只导出其中一块区域。”
- “我要遮住截图中的敏感字段，颜色尽量与背景一致。”
- “我要去掉人物背景并下载透明 PNG，但不希望照片上传。”

## 5. 信息架构

### 全局外壳

- 左侧/顶部只保留一套工具导航。
- 桌面端：窄侧栏显示五项工具；移动端：顶部当前任务 + 可展开工具菜单。
- 页面顶部显示当前任务名称、简短说明和“本地处理”状态，不再使用大幅宣传首屏。
- 移除无功能的“设置”“本地记录”“使用指南”；若保留，必须提供真实面板或页面。

### 工作区通用结构

1. 输入区：上传、拖放、粘贴和素材列表。
2. 设置区：默认折叠高级设置，只把当前任务的关键选项放在首层。
3. 预览/结果区：空状态、处理中、成功和失败均在原位展示。
4. 固定操作区：主操作与导出，按钮文案说明动作对象。

## 6. 功能需求与验收标准

### FR-1 单一导航

用户故事：作为首次用户，我希望只看一套工具入口，以便明确当前在哪个任务中。

验收标准：

- 桌面端同一视口内不再同时出现侧栏工具列表和第二套标签列表。
- 当前工具在导航中有文字、图标和选中状态。
- 切换工具后，页面标题、说明、工作区和 URL hash 同步更新。
- 键盘可依次聚焦每个工具入口，Enter/Space 可切换。

### FR-2 自动网格主流程

用户故事：作为需要快速拼图的用户，我希望上传后立即看到推荐结果，再按需微调。

验收标准：

- 上传 2–9 张支持格式图片后自动生成首个预览，或出现唯一清晰的“生成预览”主按钮。
- 图片数量不足时，页面内说明还需要几张，不弹出浏览器警告。
- 设置包含间距、背景、比例、格式和 JPG 质量；低频项可折叠。
- 支持原始、1:1、4:5、9:16、16:9 五种比例预设。
- 生成成功后导出按钮进入可用状态，并显示尺寸、格式和预计文件大小。

### FR-3 人像资源按需加载

用户故事：作为只做拼图的用户，我不希望下载与当前任务无关的人像模型。

验收标准：

- 首页 HTML 不再同步加载 `ort-wasm-data.js` 和 `portrait-model-data.js`。
- 首次进入人像抠图或点击开始处理时，按顺序加载所需脚本；重复进入不重复加载。
- 加载期间显示明确状态，失败时提供“重新加载”动作。
- 普通拼图、检测、网格和涂抹功能在人像资源加载失败时仍可正常工作。

### FR-4 页面内状态反馈

用户故事：作为连续处理图片的用户，我希望错误和进度出现在当前任务旁边，不被浏览器弹窗反复打断。

验收标准：

- 非破坏性错误、容量提醒、成功提示使用页面内提示条或轻量通知。
- 清空、删除含内容行列等不可逆动作使用产品内确认框。
- 每条错误说明“发生了什么”和“如何处理”。
- 处理中按钮显示进行状态并防止重复提交。
- 状态区域使用 `aria-live`，读屏软件能够感知变化。

### FR-5 可访问性与移动端

验收标准：

- 标签、导航、上传区、按钮和表单字段使用正确语义。
- 每个输入字段都有可点击的可见标签。
- 所有交互元素有明显 `:focus-visible` 状态。
- 正文文字与背景对比度达到 WCAG AA；错误信息不只依赖颜色。
- 触控目标至少 44×44px。
- 320、375、414、768px 宽度无页面级横向滚动，按钮文字不换成两行。
- 系统开启“减少动态效果”时，动画停留在有意义的静止状态。

### FR-6 功能回归保护

验收标准：

- 自动网格支持 2–9 张图片、PNG/JPG 导出和原有大小限制。
- 图片检测仍支持规则检测、单项/批量压缩和改尺寸。
- 网格画布仍支持增删行列、拖放、选区预览和导出。
- 图片涂抹仍支持取色、矩形覆盖、撤销、恢复和 PNG 导出。
- 人像抠图仍完全在浏览器本地运行并导出透明 PNG。

## 7. 视觉与交互设计要求

### 设计原则

- 保留深色工作台，但将背景改为低干扰的静态深灰层次。
- 保留朱红/珊瑚红作为唯一品牌主色，绿色/黄色/红色仅用于状态。
- 面板边界靠明暗和细线区分，不使用大面积模糊玻璃层。
- 按用户确认保留持续动画的小黑龙和电影背景；通过降低背景亮度、饱和度与对比度，让它们成为氛围层而非操作焦点。
- 主按钮每个任务最多一个；下载可在结果产生后成为主按钮。
- 同类控件的圆角、间距、字体和状态保持一致。

### 关键页面布局

桌面端推荐三段式：

- 72–88px 工具侧栏。
- 280–340px 输入与设置栏。
- 剩余空间作为预览/画布，底部或右下角固定导出操作。

移动端推荐单列顺序：当前工具 → 上传 → 预览 → 关键设置 → 操作；工具切换放入顶部菜单，不把五个图标挤在一行。

## 8. 性能要求

- 人像模型必须按需加载。
- 背景视频按用户确认继续静音自动播放，同时保留暂停按钮；系统开启“减少动态效果”时自动暂停。
- 示例图使用合理尺寸并延迟加载。
- 首屏必须在无 Canvas 动画、无人像模型的情况下完整可用。
- 目标：移动网络下第 75 百分位 LCP 不高于 2.5 秒；该指标需要部署后的真实数据或 Lighthouse 测试验证，当前不宣称已达到。

## 9. 成功指标

在没有用户授权分析采集前，不引入远程埋点。首版通过可重复的任务测试和性能测试评估：

- 5 名目标用户中至少 4 名无需解释即可完成 6 图自动拼图并下载。
- 中位任务完成时间不超过 60 秒。
- 五项核心任务的阻断级错误为 0。
- 人像资源不出现在普通拼图首次网络加载清单中。
- Lighthouse Accessibility 目标不低于 90，关键键盘路径人工测试通过。
- 320/375/414/768px 四档布局验收通过。

以上为发布目标，不是当前结果；需要在实现后测试。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 单文件 HTML 继续膨胀 | 修改互相影响，难以测试。 | 本期先保持部署兼容；实现过程中至少分离主题 CSS 和应用 JS，或建立模块边界。 |
| 动态加载人像脚本顺序错误 | 人像抠图失效。 | 串行加载、缓存 Promise、独立失败状态和回归测试。 |
| 改布局破坏 Canvas 坐标 | 拖放、框选或导出区域偏移。 | 所有坐标从 `getBoundingClientRect()` 与当前缩放计算；逐工具回归。 |
| 移除视觉效果被理解为“降级” | 品牌识别减弱。 | 保留朱红主色和小黑龙，但让其服务空状态和反馈，而不是持续占据背景。 |
| 常用比例自动裁切主体 | 结果不符合预期。 | 默认使用完整适配或明确标注裁切；后续补图片焦点调整。 |

## 11. 依赖与约束

- 继续使用 Netlify 静态托管，不依赖服务端运行时。
- 人像抠图依赖仓库内 ONNX Runtime 与模型资源。
- 所有第三方代码和模型许可证必须继续随部署保留。
- 不能改变“图片默认不上传”的承诺；未来若引入远程能力必须单独征得用户同意并明确标识。

## 12. 发布计划

### 阶段 A：结构与性能

- 新工作台外壳、单一导航、静态背景、无功能入口处理。
- 人像资源按需加载。
- 自动网格路径重排。

### 阶段 B：反馈与适配

- 页面内通知和确认。
- 键盘、读屏、触控目标和四档移动端适配。
- 五项工具完整回归。

### 阶段 C：增强

- 常用比例、图片焦点、统一撤销/重做、本地草稿。
- 根据真实用户测试决定是否加入批量 ZIP 和平台预设。

## 14. v1.6 拼图排版与比例补充

- 用户问题：四张原图尺寸不一致时，小图未放大填充，右下格出现大面积空白；缺少画布比例和排版入口。
- 设置入口置于预览上方：排版、画布比例、图片适配方式。保留电影背景与持续动画小黑龙，不改其他四项工具的操作流程。
- 排版支持自动、两列、三列、横排、竖排、左主图、上主图。末行不足列数时横向扩展，不生成未使用的空格。
- 比例支持自动、1:1、4:3、3:2、16:9、9:16、3:4、2:3、自定义宽高比。输出长边提供 1024、2048、4096 和原图清晰度选项。
- 默认“铺满格子（裁切边缘）”：允许小图等比放大，明确提醒裁切边缘。另提供完整显示和拉伸铺满；完整显示可能留边，拉伸可能变形。
- 上传后及设置变更后即时预览；设置变更使旧导出失效，必须重新生成，防止下载到旧比例或旧排版。
- 验收：混合尺寸四图全部铺满；零间距下所有排版无未用画布区域；1:1 导出为 2048×2048，9:16 为 1152×2048；1344 组数量/排版/比例/间距组合测试通过。
